# 05 - 息屏保活（核心难点）

**这是整个方案里最难、也最有价值的部分。**

## 5.1 问题现象

手机一息屏，SSH 就断。实测**连 20 秒都撑不过**。

```
$ ssh nubia 'while true; do date; sleep 5; done'
... 手机息屏 ...
Connection to nubia-m153 closed by remote host.
```

---

## 5.2 原因分析

这不是配置问题，是 **Android 的系统机制**。

### 完整链条

```
1. 屏幕熄灭
      ↓
2. 系统判定 Termux 为后台应用
      ↓
3. 移入 "缓存冻结组"（cached / frozen），暂停 CPU 调度
      ↓
4. sshd 进程被冻结 → TCP socket 失效
      ↓
5. 客户端报 "Connection closed by remote host"
```

### 从系统日志看到的证据

```
avc: denied { ioctl } for path=/dev/pts/...      ← SELinux 拒绝 Termux 操作伪终端
Read error from remote host ...: Software caused connection abort   ← socket 被系统干掉
DisplayState - old: 1, new: 3                    ← 屏幕熄灭，触发冻结判定
```

- `untrusted_app_27` 是 Termux 的 SELinux 域（非特权应用）
- `DisplayState` 变化是触发冻结判定的信号

### 为什么 `termux-wake-lock` 不管用

这是最容易误解的一点：

| 机制 | 作用范围 | 能否防冻结 |
|------|---------|-----------|
| `termux-wake-lock` | 防止 **CPU 休眠** | ❌ 防不住进程冻结策略 |
| 前台服务通知 | 提升优先级 | ⚠️ 部分有效，但仍会被冻结 |
| **音频播放（本方案）** | 触发**音频焦点豁免** | ✅ 有效 |

**关键区别**：Wake Lock 是"别让 CPU 睡"，而冻结是"暂停你的进程调度"——后者不受 Wake Lock 约束。

---

## 5.3 解决方案：音频焦点"免死金牌"

### 原理

Android 对**正在播放音频**的应用有特殊豁免：

系统认为它在执行"用户可感知的任务"，因此：

- ✅ 不把它移入冻结组
- ✅ 保持 WiFi 芯片在低延迟模式
- ✅ 提升 OOM 优先级，不易被内存回收杀掉

**所以只要让 Termux 持续播放一个静音音频，就能骗过系统。**

> 这是无 root 环境下唯一实测有效的手段。

---

## 5.4 实施步骤

### 第 1 步：生成静音文件

在**电脑上**做（ffmpeg 也可在手机装，但电脑更快）：

```bash
ffmpeg -y -f lavfi -i anullsrc=r=8000:cl=mono -t 65 \
  -c:a libopencore_amrnb -b:a 4.75k quiet_1min.amr
```

参数说明：

| 参数 | 值 | 原因 |
|------|-----|------|
| 格式 | **AMR**（不是 MP3） | 体积最小，只有 41 KB |
| 时长 | **65 秒** | 比循环间隔（55 秒）长，保证不断音 |
| 采样率 | 8000 Hz | AMR 要求 |
| 码率 | 4.75 kbps | 最低码率，最省资源 |

传到手机：

```bash
scp quiet_1min.amr nubia:~/.termux/quiet_1min.amr
```

### 第 2 步：保活脚本

**`~/.termux/keepalive.sh`**：

```bash
#!/data/data/com.termux/files/usr/bin/bash
# 音频焦点保活：让 Android 认为 Termux 在播放媒体，豁免息屏冻结
termux-wake-lock 2>/dev/null
[ -f ~/.termux/quiet_1min.amr ] || exit 0

if ! pgrep -f "termux-media-player play" >/dev/null 2>&1; then
    setsid nohup sh -c "while true; do
        termux-media-player play ~/.termux/quiet_1min.amr >/dev/null 2>&1
        sleep 55
    done" >/dev/null 2>&1 < /dev/null &
fi
```

```bash
chmod +x ~/.termux/keepalive.sh
```

**关键细节**：

| 写法 | 作用 |
|------|------|
| `setsid` | 脱离当前会话，SSH 断开后继续运行 |
| `nohup` | 忽略 SIGHUP |
| `< /dev/null` | 防止读 stdin 阻塞 |
| `pgrep -f "..."` | **必须用 `-f`**（匹配完整命令行），`-x` 会漏判 |
| `sleep 55` < 65 秒 | 保证音频覆盖无缝衔接 |

### 第 3 步：设为自动启动

```bash
echo '[ -x ~/.termux/keepalive.sh ] && ~/.termux/keepalive.sh' >> ~/.bashrc
```

每次打开 Termux 自动保活。

### 第 4 步：ADB 关掉系统级省电限制

加固措施，光靠脚本不够。用 ADB（见 [06-ADB指南.md](06-ADB指南.md)）：

```bash
# 把 Termux 加入 Doze 白名单
adb shell dumpsys deviceidle whitelist +com.termux
adb shell dumpsys deviceidle whitelist +com.termux.api

# 允许后台运行
adb shell cmd appops set com.termux RUN_IN_BACKGROUND allow
adb shell cmd appops set com.termux RUN_ANY_IN_BACKGROUND allow
adb shell cmd appops set com.termux WAKE_LOCK allow

# 给 Termux:API 授予媒体播放相关权限
adb shell pm grant com.termux.api android.permission.FOREGROUND_SERVICE
adb shell pm grant com.termux.api android.permission.WAKE_LOCK
adb shell pm grant com.termux.api android.permission.POST_NOTIFICATIONS
adb shell pm grant com.termux.api android.permission.READ_MEDIA_AUDIO
adb shell pm grant com.termux.api android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK
```

### 第 5 步：手机设置里手动确认

这几项 ADB 改不了，需要在手机上点：

- 设置 → 应用 → Termux → **省电策略 → 无限制**
- 多任务界面 → 长按 Termux 卡片 → **加锁**
- 设置 → 应用 → Termux → 电池 → **允许后台活动**

## 5.5 实测效果

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 息屏 20 秒 | ❌ 断 | ✅ 存活 |
| 息屏 2 分钟 | ❌ 断 | ✅ 存活 |
| 息屏 7 分钟 | ❌ 断 | ✅ 存活（已实测） |
| 整夜 | ❌ 断 | ⏳ 待验证 |

**代价**：耗电增加（音频播放持续占用 CPU/音频子系统）。这是目前无 root 方案下的必要代价。

## 5.6 验证保活是否工作

```bash
# 1. 检查播放进程
ssh nubia 'pgrep -af termux-media-player'

# 2. 检查音频焦点状态（系统层面）
adb shell dumpsys audio | grep -A3 "mFocusStack"

# 3. 让手机息屏，等 2 分钟，再看连接
adb shell input keyevent KEYCODE_SLEEP
sleep 120
ssh nubia 'echo "还活着"' && echo "✅ 保活生效"
```

## 5.7 常见问题

### `termux-media-player info` 会卡住 SSH

这个子命令会阻塞等待 APK 响应，**不要在脚本里用**。

保活循环里用的是 `play`，不会卡。

### 播放没声音但也没报错

正常。文件本身是静音的，目的是拿音频焦点，不是发声。

### 保活进程反复重启

看日志：
```bash
tail -20 ~/.termux/watchdog.log
```

如果频繁 "keepalive restarted"，可能是 AMR 文件损坏，重新生成一个。

### 耗电太快

这是必然代价。可以权衡：
- 只在需要时开保活（注释掉 `.bashrc` 里的自启）
- 白天不用时 `pkill -f termux-media-player` 停掉
- 接受"息屏会断"的现状

## 5.8 替代方案对比

| 方案 | 需 root | 效果 | 备注 |
|------|--------|------|------|
| **音频焦点（本方案）** | ❌ 不需要 | ✅ 实测有效 | 耗电 |
| **关闭 phantom process killer（见 5.9）** | ❌ 不需要（ADB 即可） | ✅ 有效 | **建议与音频焦点一起用** |
| Wake Lock | ❌ | ❌ 无效 | 只防 CPU 休眠 |
| 前台服务通知 | ❌ | ⚠️ 部分有效 | Android 16 上仍会被冻结 |
| 开发者选项"不锁定屏幕" | ❌ | ⚠️ 屏幕不灭而已 | 绕不过问题 |
| 修改系统冻结策略 | ✅ 需要 | ✅ 最彻底 | 需 root |

## 5.9 ⚠️ 另一个隐藏杀手：phantom process killer

**这一节是实测发现的，很可能是你「SSH 莫名其妙断掉」的第二个原因。**

音频焦点解决的是「息屏后进程被冻结」，但 **Android 12+ 还有一个独立的机制**：限制单个 App 能派生的子进程数量（默认 32 个），超了就直接杀。

Termux 恰好是个「一个 App 派生一堆 Linux 进程」的典型：`sshd`、`crond`、`runsvdir`、桌面组件……**很容易就超**。

### 怎么发现它正在盯你的进程

```bash
adb shell "dumpsys activity processes | grep PhantomProcessRecord"
```

实测输出（18 个进程正在被监控，注意 `sshd` 和 `crond` 都在里面）：

```
proc #1: PhantomProcessRecord {b6f1fbb 24150:3337:sshd/u0a246}
proc #3: PhantomProcessRecord {631eb16 24153:3337:crond/u0a246}
proc #6: PhantomProcessRecord {1619b54 24379:3337:dbus-launch/u0a246}
proc #8: PhantomProcessRecord {f7d53f2 24397:3337:xfconfd/u0a246}
...
```

**只要出现在这个列表里，就随时可能被系统杀掉。**

### 解法：ADB 两条命令关掉（不需要 root）

```bash
# 1. 关闭监控开关
adb shell settings put global settings_enable_monitor_phantom_procs 0

# 2. 把上限拉到最大（持久化配置）
adb shell device_config set_sync_disabled_for_tests persistent
adb shell device_config put activity_manager max_phantom_processes 2147483647
```

### 验证

```bash
adb shell settings get global settings_enable_monitor_phantom_procs
# 应输出 0（之前是 null，表示用默认值=开启）

adb shell device_config get activity_manager max_phantom_processes
# 应输出 2147483647
```

### ⚠️ 注意事项

| 项 | 说明 |
|----|------|
| **重启后会重置** | `device_config` 的设置在部分机型重启后失效，需重新执行 |
| **`set_sync_disabled_for_tests persistent`** | 这行是为了防止 `device_config` 被系统自动同步回默认值，**必加** |
| **对电池有影响** | 关掉限制后系统可能更激进地杀后台，建议配合「电池优化白名单」 |
| **不是 root 操作** | 实测普通 ADB 权限足够，**不需要 root 也不需要 Shizuku** |

### 建议同时做：电池优化白名单

```bash
adb shell dumpsys deviceidle whitelist +com.termux
```

这三层（**音频焦点 + 关 phantom killer + 电池白名单**）叠起来，后台存活才真正稳。
