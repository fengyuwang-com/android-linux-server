# 03 - 工具链与镜像源

## 3.1 ⚠️ 关键坑：软件源必须换

**Termux 默认镜像源在国内完全不可达。** 这是整个部署过程中最容易卡死的一步。

### 默认源的问题

默认源是 `mirror.accum.se`（**瑞典**）。国内网络连它会超时 30 秒以上。

### 迷惑性症状

| 现象 | 说明 |
|------|------|
| `pkg install` 卡住不动，无任何下载进度 | 真实状态：连接建立不了 |
| `pkg update` 却显示 "Hit" | **假象**：那是读本地缓存，不是真连上了 |
| 进程状态是 `S`（睡眠）而非 `R`（运行） | 在等网络超时 |
| deb 缓存 0 文件 / 0 字节 | 一个包都没下下来 |

> **判断技巧**：如果 `pkg install` 超过 2 分钟没有任何下载百分比，基本可以确定是源的问题，直接 Ctrl+C 换源。

### 解法：换清华源

```bash
# 1. 备份原配置
cp $PREFIX/etc/apt/sources.list $PREFIX/etc/apt/sources.list.bak

# 2. 换成清华源
echo "deb https://mirrors.tuna.tsinghua.edu.cn/termux/apt/termux-main stable main" > $PREFIX/etc/apt/sources.list

# 3. 更新
pkg update
```

### 实测速度对比

| 镜像 | 响应时间 | 可用性 |
|------|---------|--------|
| **清华 TUNA** | **0.58 秒** | ✅ 推荐 |
| 中科大 USTC | 5.4 秒 | ✅ 可用 |
| 官方 CDN | 9.0 秒 | ⚠️ 慢 |
| 瑞典 accum.se | **超时** | ❌ 不可用 |

测速方法：
```bash
time curl -sI https://mirrors.tuna.tsinghua.edu.cn/termux/apt/termux-main/ >/dev/null
```

### 附加源：x11-repo

图形界面组件不在主源里，需要单独加：

```bash
pkg install -y x11-repo
pkg update
```

## 3.3 ⚠️ 第二个坑：libc++ 版本导致的符号缺失

### 症状

装某些包（如 `ffmpeg`）时，post-install 脚本失败：

```
CANNOT LINK EXECUTABLE "ffmpeg": cannot locate symbol
"_ZNSt6__ndk127__from_chars_floating_pointIfEENS_19__from_chars_resultIT_EEPKcS5_NS_12chars_formatE"
referenced by "/data/data/com.termux/files/usr/lib/libplacebo.so"
```

然后 apt 报依赖错误，后续包（依赖 ffmpeg 的）全部装不上：

```
dpkg: dependency problems prevent configuration of firefox:
 firefox depends on ffmpeg; however:
  Package ffmpeg is not configured yet.
```

### 原因

**`libc++` 版本比新装的包旧。**

具体机制：新编译的 `libplacebo.so` 用新版 libc++ 编译，调用了 `std::from_chars` 的浮点重载 —— 这个符号在旧版 libc++ 里不存在。

```
libc++ 27c  ← 已安装（旧）
libc++ 29   ← libplacebo 需要（新）
```

### 诊断

```bash
# 查看已装版本
dpkg -l | grep libc++

# 查看可用版本
apt-cache policy libc++
```

如果 Installed 比 Candidate 旧，就是这个原因。

### 解法

```bash
pkg install -y "libc++=29"
```

> 版本号按 `apt-cache policy` 显示的 Candidate 填。

装完 ffmpeg 和所有依赖它的包会自动完成配置。

### ⚠️ 相关坑：`pkg upgrade` 会打死 SSH

**`pkg upgrade` 替换 sshd 二进制时，会把当前 SSH 会话连同进程一起打死**，而且 cron 看门狗也同时被杀，无法自愈。

**症状**：
```
Connection to nubia-m153 closed by remote host.
```
之后重连被拒（端口 8022 不通）。

**解法 1（推荐）**：装一个 apt 后置钩子，每次 dpkg 操作后自动拉起 sshd：

```bash
cat > $PREFIX/etc/apt/apt.conf.d/99-restart-sshd << 'EOF'
DPkg::Post-Invoke { "pgrep -f \"sshd -D\" >/dev/null 2>&1 || (sshd >/dev/null 2>&1 &)"; };
EOF
```

**解法 2**：用 ADB 救援（见 [06-ADB指南.md](06-ADB指南.md)）。

> **结论**：任何可能动到 sshd 的操作前，先装好这个钩子，或者确保 USB 线在手边。

## 3.5 Termux 特有的路径问题

### `/tmp` 不可写

Termux 里 `/tmp` 是 Android 系统的目录，应用无权写入：

```bash
$ echo hi > /tmp/test
bash: /tmp/test: Permission denied
```

**解法**：用 `$PREFIX/tmp` 或家目录。

```bash
echo hi > $PREFIX/tmp/test    # 可写
echo hi > ~/test              # 可写
```

> 这个坑很隐蔽，因为很多工具的默认临时目录是 `/tmp`。

### 没有 `which`

Termux 默认不装 `which`：

```bash
$ which python
bash: which: command not found
```

**替代**：
```bash
command -v python
type python
```

### 没有 `/etc/os-release`

Termux 是应用沙箱，没有标准 Linux 的 `/etc/os-release`：

```bash
$ cat /etc/os-release
cat: /etc/os-release: No such file or directory
```

**影响**：某些工具靠读这个文件判断发行版，读不到会行为异常。

**解法**：如需，可以在 `$PREFIX/etc/os-release` 造一个。
