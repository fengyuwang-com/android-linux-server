# 07 - 自愈机制

**目标**：任何环节挂掉，系统能自己恢复，不需要人工干预。

**为什么需要多层**：单机制都不可靠——`runsvdir` 会随 Termux 主进程被杀而消失，cron 也会一起被杀。所以做了 5 层兜底。

---

## 第 1 层：runsvdir 进程守护（最快）

`termux-services` 提供进程管理。

```bash
pkg install -y termux-services
sv-enable sshd
sv-enable crond
```

### 关键机制

`termux-services` 通过 `$PREFIX/etc/profile.d/start-services.sh` 在每次登录 shell 时自动启动 `runsvdir`：

```bash
# 该文件内容
export SVDIR=$PREFIX/var/service
export LOGDIR=$PREFIX/var/log
(service-daemon start >/dev/null 2>&1 & )
```

`runsvdir` 常驻后，为每个服务启动一个 `runsv` 监督进程。**服务被杀立刻自动重启**。

### 验证

```bash
pgrep -f runsvdir        # 守护进程
pgrep -f "runsv sshd"    # sshd 的监督进程
pgrep -f "sshd -D"       # sshd 本体
```

> ⚠️ **必须用 `pgrep -f`**（匹配完整命令行）。用 `pgrep -x`（精确匹配进程名）会漏判——实际进程名带参数（如 `sshd -D -e`），`-x` 匹配不到。

**实测恢复时间**：5 秒。

---

## 第 2 层：cron 看门狗（最可靠）

即使 `runsvdir` 也没了，cron 每分钟检查一次，同时守护 **sshd、保活、VNC** 三样。

### `~/.termux/watchdog.sh`

```bash
#!/data/data/com.termux/files/usr/bin/bash

# sshd 守护
if ! pgrep -f "sshd -D" >/dev/null 2>&1; then
    sshd 2>/dev/null
    echo "$(date '+%F %T') sshd restarted" >> ~/.termux/watchdog.log
fi

# 保活守护
if [ -f ~/.termux/quiet_1min.amr ]; then
    if ! pgrep -f "termux-media-player play" >/dev/null 2>&1; then
        setsid nohup sh -c "while true; do
            termux-media-player play ~/.termux/quiet_1min.amr >/dev/null 2>&1
            sleep 55
        done" >/dev/null 2>&1 < /dev/null &
        echo "$(date '+%F %T') keepalive restarted" >> ~/.termux/watchdog.log
    fi
fi

# VNC 桌面守护（靠标记文件控制是否自启）
if [ -f ~/.vnc/autostart ]; then
    if ! pgrep -f "Xvnc :1" >/dev/null 2>&1; then
        setsid nohup ~/start-vnc.sh >/dev/null 2>&1 < /dev/null &
        echo "$(date '+%F %T') vnc restarted" >> ~/.termux/watchdog.log
    fi
fi
```

### 安装

```bash
chmod +x ~/.termux/watchdog.sh
(crontab -l 2>/dev/null | grep -v watchdog.sh; echo "* * * * * ~/.termux/watchdog.sh") | crontab -
```

> 这行命令的写法保证了**幂等**：先去掉已有的 watchdog 行，再加一条，避免重复。

### 控制 VNC 是否自启

```bash
touch ~/.vnc/autostart    # 开启：桌面挂了自动拉起
rm ~/.vnc/autostart       # 关闭：不自动启动（省电）
```

### 查看日志

```bash
tail -20 ~/.termux/watchdog.log
```

输出示例：
```
2026-09-16 21:30:15 sshd restarted
2026-09-16 22:10:03 keepalive restarted
```

**实测恢复时间**：60 秒内。

## 第 3 层：.bashrc 自启（兜底）

Termux 主进程被系统回收后重新打开时，`.bashrc` 会执行，拉起所有服务。

### `~/.bashrc` 末尾追加

```bash
# 自动保活
[ -x ~/.termux/keepalive.sh ] && ~/.termux/keepalive.sh

# 自动启动 sshd
if ! pgrep -f "sshd -D" >/dev/null 2>&1; then
    sshd 2>/dev/null
fi
```

> **这一层是 ADB 救援能生效的关键**——见 [06-ADB指南.md](06-ADB指南.md)。
> 但注意：`.bashrc` 只在**新的交互式会话**时执行，已有会话不会重新触发。

**实测恢复时间**：5 秒。

## 第 4 层：Termux:Boot（开机自启）

手机重启后的自动拉起。需要从 F-Droid 装 **Termux:Boot**。

### 配置

1. 从 F-Droid 安装 Termux:Boot
2. **手动打开一次 Termux:Boot**（必须，用于激活其自启权限）
3. 创建启动脚本：

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/start-services.sh << 'EOF'
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
sleep 3

# 启动 sshd
if ! pgrep -f "sshd -D" >/dev/null 2>&1; then
    sshd 2>/dev/null
fi

# 启动音频保活
if [ -f ~/.termux/quiet_1min.amr ]; then
    setsid nohup sh -c "while true; do
        termux-media-player play ~/.termux/quiet_1min.amr >/dev/null 2>&1
        sleep 55
    done" >/dev/null 2>&1 < /dev/null &
fi

# 启动 termux-services
service-daemon start 2>/dev/null
EOF
chmod +x ~/.termux/boot/start-services.sh
```

> ⚠️ **这一层未经验证**——需要真正重启手机才能确认。文档如实标注。

## 第 5 层：apt dpkg 钩子（补 sshd 被打死的场景）

### 问题

`pkg upgrade` 替换 sshd 二进制时会把**当前 SSH 会话打死**，而 cron 看门狗也同时被杀，无法自愈。

**症状**：
```
Connection to nubia-m153 closed by remote host.
```

### 解法

```bash
cat > $PREFIX/etc/apt/apt.conf.d/99-restart-sshd << 'EOF'
DPkg::Post-Invoke { "pgrep -f \"sshd -D\" >/dev/null 2>&1 || (sshd >/dev/null 2>&1 &)"; };
EOF
```

**原理**：`DPkg::Post-Invoke` 是 apt 的后置钩子，每次 dpkg 操作**全部完成后**执行。这里检查 sshd 是否活着，不在就拉起来。

> 注意转义：`\"` 是为了让引号在 apt 配置和 shell 之间正确传递。

这层是**实践中补出来的**——原本的 4 层设计没有覆盖"装包打死 sshd"这个场景，是踩了三次坑之后加的。

## 实测结果汇总

| 测试场景 | 恢复时间 | 恢复者 |
|---------|---------|--------|
| 息屏 7 分钟 | 无断连 | 音频保活 |
| `kill sshd` | **5 秒** | runsvdir |
| `force-stop com.termux` 后重开 | **5 秒** | .bashrc |
| kill runsvdir + sshd + runsv | **60 秒内** | cron 看门狗 |
| `pkg upgrade` 打死 sshd | 装包结束时 | dpkg 钩子 |
| 手机重启 | ⏳ 待验证 | Termux:Boot |

## 一键健康检查

```bash
ssh nubia 'for p in runsvdir "runsv sshd" "sshd -D" crond "Xvnc :1" "termux-media-player"; do
  printf "%-24s: " "$p"
  pgrep -f "$p" >/dev/null && echo OK || echo FAIL
done'
```

预期全部 `OK`（`Xvnc :1` 和 `termux-media-player` 只在真启动时才是 OK）。

---

## 可靠性排序

实践中得出的排序（从最可靠到最不可靠）：

```
dpkg 钩子  >  cron 看门狗  >  .bashrc  >  runsvdir
```

**反直觉的地方**：`runsvdir` 排最后——因为它是 Termux 的子进程，Termux 被杀它必死。而 cron 是独立的 daemon，存活概率更高。
